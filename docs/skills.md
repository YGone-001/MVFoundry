# Skills

## Project-owned universal Skills

Five complete Skills live in `.agents/skills/`:

| Skill | Purpose |
|---|---|
| `music-video-director` | Beat-grid evidence, manual timing/sections, optional lyrics, creative direction, director plans and frame-accurate storyboards |
| `visual-identity-continuity` | Style profiles, creative briefs, palettes, character/environment contracts, continuity references and asset-direction audits |
| `ai-shot-production` | Provider-neutral shot contracts, asset requirement manifests, keyframes, hashes, provenance, authorization and approved media/audio integration |
| `remotion-mv-compositor` | Frame clock, scene registry, Canvas/Video/Hybrid renderers, audio mixing, preproduction plan/storyboard compilation, trusted modules, local media and rendering |
| `music-video-quality-gate` | Evidence-based acceptance for timing, beat-grid uncertainty, manual overrides, storyboard coverage, asset fulfillment, candidate compilation, decoded audio/video and PASS/FAIL/BLOCKED/NOT RUN |

Each has YAML frontmatter whose `name` matches its folder and contains activation conditions, input and output contracts, workflow, prohibited actions, acceptance checks and failure behavior. They are song-independent and contain no private references or production prompts.

## Official Remotion Skills

The seven official Remotion Skills are not vendored. See `docs/official-skills.md` for the source revision, install command and licensing note.

## Discovery

- Agents with native `.agents/skills` discovery find the five project Skills and any installed official Skills.
- Agents without native discovery must read `AGENTS.md` and the five `SKILL.md` files explicitly.
- Do not publish a lockfile that claims Skills are installed when their files are absent.

`ai-shot-production` also carries the generation-job rules: capability validation before submission, `pending` intake for every generated byte, deterministic identity against duplicate submissions, and `NOT_GRANTED` live execution. It additionally covers the provider media lifecycle: output kind bound to the submitted operation, task-bound result identity, reference disclosure as a separate decision from local approval, secure retrieval with a trusted delivery-host policy, provenance-preserving normalization, and retrieval failure that never becomes a second billable submission.
